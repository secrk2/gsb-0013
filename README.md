# 报关通 · 报关行自研报关作业与合规风控平台

进出口报关单**全生命周期**管理 + 合规风控骨架。已落地「**报关作战台**」「**委托与客户**」
「**逻辑审核与查验排期**」三条主线。

- 后端：Python 3.11 + FastAPI + SQLAlchemy + SQLite，监听 **7106**
- 前端：零构建原生 SPA（HTML/CSS/JS），由 Nginx 在 **8106** 托管并反代 `/api → 7106`
- 一键拉起：`docker compose up -d --build`，打开 http://localhost:8106

---

## 一键启动

```bash
docker compose up -d --build
# 前端/入口：http://localhost:8106
# 后端直连：http://localhost:7106/api/health
```

首次启动后端会**自动建表并预置演示数据**（SQLite 存于命名卷 `bgt-data:/data`）。
重置演示数据：

```bash
docker compose down -v && docker compose up -d --build
```

## 功能与验收点对照

### 1. 委托到客户做成链路，非法回退拦下说原因
链路强约束（见 `app/deps.py::ensure_active_contract`、`app/routers/clients.py`）：

```
企业备案(filing) ──审核通过──> 已备案(active) ──签署──> 委托合同生效(active) ──> 报关单立项(entrusted)
```

- 给**备案中/被驳回**企业签合同 → 409，返回具体原因（含驳回原因）。
- 凭**未生效/他企业**合同立项 → 409，说明必须先签生效合同。
- 状态机集中在 `app/models.py::guard_transition`：终态不可变更、不允许跳态/回退，
  非法时返回形如「不允许从 X 直接变为 Y，当前允许的下一步是…」的可读原因。
  唯一合规回退通道 `审单中 → 已录入（退单补录）`、`查验中 → 审单中（查验异常重审）`已显式放行。

### 2. 企业名脱敏 + 二次确认 + 留痕
- 默认展示名 = 字号缩写 + 编号（如「华腾 E0101」），统一社会信用代码同步掩码。
- 报关员查看全名必须**二次确认并填写 ≥10 字理由**，写入 `name_reveals` 表。
- 「全名查看留痕」页（监管员看全部、报关员看自己的）可审计追溯。

### 3. 报关作战台
- 全行六态待审漏斗 + 按企业聚合的迷你漏斗/待审 KPI。
- 查验排期表（今日数、逾期红点）。
- 征税红点：**逾期未缴（红）**、**3 日内到期（黄）**，可一键跳单据处置。
- 响应式适配 **1440 桌面 / 1024 平板 / 390 手机**（断点 1200px、720px，侧栏在窄屏转横向标签）。

### 4. 企业间隔离，越权给错误态而非空白页
- 企业管理员只能读本企业数据；列表带他企业 `enterprise_id` → 403；
  直接打开他企业报关单详情 → **明确的错误态页**（错误码 + 原因 + 返回入口），不是空白页。
- 越权执行非本角色操作同样被状态机角色表拦下（403 + 原因）。

### 5. 口岸离线：不能拿旧状态糊弄，恢复后合并且幂等
- 断网时顶部红色横幅常驻；所有缓存视图打「🕓 离线缓存 · 截至 …」水印，
  并明示**非实时状态**、不提供误导性的操作按钮。
- 断网可：①本地起草报关单（带稳定 `idem_key` + `client_ref`）②本地排队流转（带 `client_event_id`）。
- 恢复联网后自动补传：
  - 建单走 `Idempotency-Key` 与 `client_ref` 双保险，**绝不产生重复报关单**，重放返回首次结果；
  - 流转走 `/declarations/{id}/sync-offline`，在服务端逐条重放状态机：
    已应用→跳过（幂等）、非法/构成回退→进**冲突清单**弹给人工，绝不静默覆盖。
- 在线流转带 `expected_version` 乐观锁：版本过期返回 409 `version_conflict`，
  前端拉最新快照后弹出「合并确认」，基于新版本重提。

> 浏览器里演示断网：DevTools → Network → Offline，或直接拔网；恢复后会自动触发合并。

### 6. 逻辑审核 → 监管场站排期 → 链式改派（查验甘特）

入口：侧栏「🗓️ 查验排期」，或在报关单详情的查验卡中操作（`app/routers/inspections.py`、
`app/services/scheduling.py`、`frontend/js/inspections.js`）。

**① 逻辑审核是排期前置**

- 海关审单员在审单中单据上提交「单证一致 + 归类/价格逻辑」审核结论：
  `pass_inspect 通过·布控查验` / `release 审结放行` / `return 退回补录`。
- 没有 `pass_inspect` 结论一律不能占车位/派查验员——裸点「布控查验」或直接调排期接口都返回
  409 `review_required`，防止绕过审核。

**② 双甘特 + 拖拽排期，冲突逐条标红、点开看原因**

- 「按车位泳道 / 按查验员泳道」两种泳道 × 「日甘特 / 周甘特」两种粒度，卡片可拖拽，30 分钟吸附。
- 硬冲突由服务端统一判定，**不是笼统弹报错**，每条返回结构化明细（code/原因/冲突关联单），
  甘特加载即逐单体检、红卡脉冲提示，点开卡片或冲突条目可看完整原因并一键跳到关联单：
  - `bay_overlap` 同车位同时段两单占；
  - `inspector_overlap` 同查验员同时段两单；
  - `bay_cert_mismatch` / `inspector_cert_mismatch` 车位/查验员资质不匹配
    （按 HS 章+货名推断 `cold 冷链 / food 食品 / heavy 重机 / danger 危化 / normal`）；
  - `bay_out_of_service` 车位故障停用、`inspector_unavailable` 查验员请假。
- 拖拽落点超出场站每日作业时段（含跨午夜）或 7 天排期窗口、或排到过去时间 →
  **二次确认并填写 ≥5 字原因**才保存，写 `window_override` 留痕。
- 表单支持「🎯 推荐最早空闲时段」：自动找资质匹配且车位/查验员双空闲的时段。

**③ 改派（车故障 / 人请假）：解绑重派 + 链式重排**

- 「改派」分 **预览 → 确认** 两步；确认时服务端按最新数据重新推演，不信任客户端回传方案。
- 当前单解绑到新时间/车位/查验员后，**同一场站、计划时间在其后的单按时间升序单向扫描、
  仅向后顺延**（四阶段偏好：同车位同人 → 同人换车位 → 同车位换人 → 均可换）；
  只后移不回看，**结构上不可能产生环形依赖**。
- 遵循最小移动：原车位/原人/原时间仍可行的后续单绝不挪动（包括已二次确认的夜班超窗口排期）。
- **已放行 / 已结关单绝不移动**（排期锁定，拖/改/取消全部 409）；已完成、查验中单作为固定占用；
  14 天窗口内找不到合规资源的单进「阻塞，需人工处理」清单，逐条给原因。
- 一次改派所有变动单共享 `reassign_batch_id`，逐单写 `reassign / chain_move` 留痕；
  可顺带把故障车位 / 请假查验员登记停用。

**④ 三种空/错态严格分开（不统一成「暂无数据」）**

| 场景 | 界面 |
| --- | --- |
| 排期加载失败（断网/5xx） | 错误态：错误码 + 原因 + 「重新加载」 |
| 该单无排期（200 空列表） | 「🧭 该单暂无查验排期」+ 按状态给出「逻辑审核 / 安排查验」入口 |
| 排期全部取消 | 「🚫 N 次查验排期均已取消」+ 逐次取消记录 + 「重新安排查验」 |

**⑤ 查验及时率：两个口径都算，公式写在界面上**

「📊 查验及时率（双口径）」弹窗同时给出，可切月份、看近 6 个月双柱走势：

- **时效口径** = 实际查验完成日 ≤ 应查验日(`due_at`) 的单数 ÷ 当月应查验单数（已取消不计分母）；
- **单量口径** = 当月已完成查验单数（含异常）÷ 当月派出的查验排期单数（**含已取消**）。

> 两个口径回答不同问题：频繁改派会把实际查验日推后，**时效口径走低**；
> 而改派后只要完成仍计入，**单量口径可以保持高位**。预置的 **2026-08** 即演示两口径反向
> （36.4% vs 91.7%），界面上明确标注「考核以哪个为准请切换查看，勿混用」。

## 目录结构

```
.
├── docker-compose.yml          # 一键拉起 backend(7106)+frontend(8106)
├── backend/
│   ├── Dockerfile
│   ├── requirements.txt
│   ├── smoke_test.py
│   └── app/
│       ├── main.py             # FastAPI 入口、统一错误格式（含 details 冲突明细）
│       ├── migrate.py          # 启动轻量迁移：补列 + users 枚举重建（旧库平滑升级）
│       ├── models.py           # ORM + 状态机（guard_transition 单一事实来源）
│       ├── deps.py             # 登录态、企业间隔离、委托链路校验
│       ├── security.py         # pbkdf2 口令哈希、会话 token
│       ├── schemas.py          # 入参/序列化
│       ├── seed.py             # 预置数据（场站台位/查验员/冲突/链式/双口径月度）
│       ├── services/
│       │   └── scheduling.py   # 资质推断、冲突引擎、窗口校验、链式重排（无环保证）
│       └── routers/ (auth / clients / declarations / dashboard / inspections)
└── frontend/
    ├── Dockerfile
    ├── nginx.conf              # 8106 静态托管 + /api 反代 7106
    ├── index.html
    └── css / js (api、offline、app、inspections)
```

## 本地开发（不用 Docker）

```bash
cd backend
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
BGT_DATA_DIR=./data uvicorn app.main:app --reload --port 7106
# 前端可用任意静态服务器，把 /api 代理到 127.0.0.1:7106
```
